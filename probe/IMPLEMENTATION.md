| 功能 | 当前行为 |
| --- | --- |
| 系统管理入口 | 探针管理、连接检查、接入设置、选择机器更换地址 |

| 单个整合 Agent | Nezha 监控 + DBoard 代理节点内核 |
| 管理通信 | HTTPS、WebSocket、gRPC 均使用探针入口；Connector 在面板侧主动连接 |
| 内部隔离 | 节点不接收面板域名、内部机器 ID、机器 Token |
| 业务功能 | 保留用户分流、前置认证、负载均衡、连接限制和出口统计 |
| 域名迁移 | 目标验证、备用入口、离线任务、状态反馈与重新连接 |
| 流量上报 | 持久队列、批次去重、永久错误隔离 |
| 节点升级 | 校验、连接恢复验收与失败回退 |
| 删除同步 | 撤销身份、清理监控、幂等重试，旧身份不能回流 |
| 排序同步 | 服务器管理保存后同步探针默认顺序 |
| 显示 ID | 可按当前顺序重排，内部身份与关联不变 |
| 后台限制 | 60 秒一次性授权、2 小时入口会话、未授权 404、公开首页无入口 |

- 安装基础阶段另有真实 Dashboard/Agent 的监控、VLESS、计费转发、地址迁移和重启持久化测试；其面板端为 fixture，实际 PHP 行为由集成测试覆盖。

## 必须保留的边界

- 新域名要先指向同一探针服务并配置三个通道；跨主机还需搬迁数据库、注册表与密钥。
- 所有已知入口都断开时，不能向离线节点凭空下发未知地址。
- root/宿主机管理员仍可读取节点本机信息，不能承诺伪装后不可发现。
- 原厂哪吒与整合 Agent 的程序、配置、服务必须保持独立。
- 本文是实现和验收记录，不包含生产域名、账号密码、密钥或业务数据库；部署者应私下保留自己的版本与备份记录。
